# ADR-0003：平台契约由软件仓库定义

状态：Accepted  
适用范围：ToolBox 软件仓库和插件仓库

## 决策

ToolBox 软件仓库定义平台实现、Plugin API、Manifest、Worker 协议、安装格式和通用 UI 契约。插件仓库消费这些契约；软件与插件发生冲突时，插件必须适配软件。

不得为了维持单个插件的旧行为，在 Host、Core 或 Worker 中加入插件类型、Plugin ID、业务字段或专用条件分支。平台契约确需演进时，先在软件仓库完成设计、兼容性测试和 SDK/DevKit 发布，再升级插件。

## 版本选择

- 已发布插件以其声明支持的 ToolBox Release、SDK 和 DevKit 为准。
- 联合开发未发布能力时，跨仓任务必须记录准确的软件 commit 或 tag。
- 未绑定软件版本时，插件不得把软件仓库 `main` 的临时行为当成已发布契约。

## 冲突解决顺序

1. 用户对当前任务的明确要求。
2. 软件仓库兼容性测试和实际实现。
3. 已发布 SDK、DevKit 和软件协议文档。
4. 插件兼容矩阵。
5. 插件实现、Manifest 和 README。

软件仓库内部的文档、测试和实现不一致时，以兼容性测试和实际实现为最终行为依据，并同步修正文档或测试。

## 结果

插件可以独立开发和发布，但不能重新解释平台协议。跨对话恢复时只要读取工作区路由、目标仓库 AI 入口、当前任务和兼容矩阵，就能确定权威源与正确的升级顺序。
