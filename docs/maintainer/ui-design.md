# ToolBox 最终软件 UI 设计方案

> 文档状态：已确认的设计基线
>
> 适用范围：ToolBox 软件平台、通用 Host、后续 WPF 实现
>
> 当前预览：[`design-previews/toolbox-bloom-final-preview.html`](../../design-previews/toolbox-bloom-final-preview.html)

这份文档是 ToolBox UI 的长期设计依据。压缩对话、切换对话或继续开发前，应先阅读本文件和根目录的 `WORKSPACE.md`。

## 1. 产品定位

ToolBox 是一个轻量的插件外壳，不为某一个插件定制页面。

```text
第三方插件
  → Plugin SDK
  → Manifest / .tpk
  → ToolBox 安装与发现
  → 通用工作区
  → 通用状态卡片、详情弹窗和区块渲染
  → OutOfProcess Worker
```

UI 设计必须满足：

- Host 负责导航、布局、主题、状态、生命周期和错误展示；
- 插件负责自己的名称、业务状态、按钮文字、指标、列表和日志内容；
- 插件不能注入 WPF 页面，不能要求 Host 为某个 Plugin ID 增加专用布局；
- 新增普通插件时，不修改 ToolBox Host 的 UI 源码；
- 音频、键鼠、网络、后台任务等插件都使用同一套通用 UI；
- 页面优先服务于操作，不堆放架构说明和宣传文案。

## 2. 视觉方向：Bloom Space

整体采用深色动态玻璃风格，但控制装饰密度，避免“满屏圆角卡片、满屏小字和大面积粉色”。

### 视觉原则

- 深色基础背景，使用两处缓慢移动的高斯光晕制造空间感；
- 玻璃面板用于区分层级，不是每个元素都使用透明效果；
- 卡片使用中等圆角，不使用过度胶囊化；
- 细边框、内侧高光和柔和阴影用于建立层次；
- 强调色只用于主要按钮、选中状态、焦点和状态提示；
- 标题、按钮和状态清晰优先，装饰性文字全部删除；
- 主题切换改变整个视觉系统，而不是只替换一个强调色。

## 3. 顶部导航

顶部区域保持固定高度，内容分为三组：

```text
ToolBox 品牌        总览 / 插件 / 活动 / 设置        系统状态 / 同步 / 设置快捷入口
```

### 固定内容

- 左侧：ToolBox Logo 和名称；
- 中间：总览、插件、活动、设置；
- 右侧：系统正常状态、同步状态、设置齿轮按钮；
- 右上角不放主题切换，不放强调色切换，不使用容易被误解为日间模式的图标。

### 设置入口

右上角齿轮按钮与顶部“设置”导航指向同一个设置页面。

主题选择只能出现在“设置 → 外观”，不能出现在顶部快捷操作区。

## 4. 页面结构

### 4.1 总览

总览是默认进入的工作区，结构固定为：

```text
自定义工作区标题                         刷新状态 / 安装插件

系统状态条：系统状态 · Host · Worker · 数据保留

统计摘要：已安装 · 运行中 · 需关注 · 数据保留

已安装插件                              最近活动
插件卡片网格                            Host 活动时间线摘要
```

总览只显示用户需要决策的信息：

- 插件名称、类型和发布者；
- 当前状态；
- 必要指标；
- 主要操作；
- 打开详情入口。

不显示以下内容：

- `BLOOM SPACE`、`WORKSPACE HEALTH`、`EVENT STREAM` 等装饰性英文；
- 重复解释 Host、Worker 和插件边界的长句；
- 每张卡片都重复出现的说明文字；
- 不会帮助用户完成操作的辅助小字。

### 4.2 插件

插件页面用于管理所有已安装插件：

- 全部；
- 运行中；
- 已停用；
- 需关注；
- 搜索插件；
- 排序；
- 安装插件；
- 插件尺寸和更多操作。

筛选、排序和搜索只影响插件列表，不改变 Host 的页面结构。

### 4.3 活动

活动页面显示 Host 统一记录的事件：

- 安装；
- 启用、停用和卸载；
- Worker 启动、停止和崩溃；
- 搜索、连接和业务操作错误；
- 需要重启。

默认只显示事件标题、时间、插件和必要详情。完整错误信息通过“查看详情”进入弹窗，不在时间线上展开大段文本。

### 4.4 设置

设置使用左侧分类导航，右侧显示当前分类内容：

- 外观；
- 插件管理；
- 数据与运行；
- 关于。

设置页不使用大量说明段落。每一项使用“名称 + 控件”，只有不直观的选项才增加一句简短提示。

## 5. 文字与字体规范

### 字体

```text
标题：Segoe UI Variable Display
正文：Segoe UI Variable Text
中文回退：Microsoft YaHei UI
代码和标识符：Cascadia Code / Consolas
```

### 字号层级

| 用途 | 字号 | 说明 |
| --- | ---: | --- |
| 页面主标题 | 29–40px | 每页最多一个视觉主标题 |
| 区块标题 | 17–20px | 用于插件区、活动区、设置区 |
| 插件名称 | 13–15px | 卡片中最重要的识别信息 |
| 正文和主要按钮 | 12–14px | 保证可读性和操作清晰 |
| 状态、版本、时间 | 11–12px | 只显示必要元数据 |
| 代码、路径、ID | 10–11px | 仅出现在详情或诊断区域 |

### 文案规则

- 使用短句和主动动词，例如“启用”“停用”“连接”“刷新”；
- 一个控件只表达一个动作；
- 不用宣传语代替功能说明；
- 不为了填充空间添加说明文字；
- 插件业务文字由插件决定，Host 不替插件改写；
- Host 架构说明只放在“关于”和诊断信息中；
- 英文只保留插件原始名称、API 名称、错误码、运行模式和必要标识符。

## 6. 总览标题自定义

设置 → 外观中提供“工作区标题”：

- 默认中文标题：`让工具各司其职。`；
- 用户可以输入自己的标题；
- 最大长度 28 个字符；
- 输入后实时更新总览页面；
- 使用本地设置保存；
- 支持恢复默认；
- 未自定义时，标题跟随 Host 语言切换；
- 自定义后不被语言切换覆盖；
- 长标题允许合理换行，但不能撑破页面布局。

## 7. 完整主题系统

ToolBox 内置四套完整主题。主题必须同时改变背景、玻璃层、文字、边框、光晕、按钮和阴影，不是只改变 `accent`。

### 7.1 紫夜 Violet Night

- 默认主题；
- 深黑蓝基础背景；
- 紫色和淡 lavender 光晕；
- 冷白文字；
- 紫色主要按钮和焦点状态；
- 表现为安静、精致的 Bloom Space。

### 7.2 冰川 Arctic Glass

- 深蓝灰背景；
- 冰蓝和青色光晕；
- 偏冷的玻璃面板；
- 更强的科技感和信息清晰度。

### 7.3 琥珀 Ember

- 深棕黑和酒红背景；
- 琥珀、铜色和暖白文字；
- 温暖但克制的玻璃层；
- 偏高级编辑工具和创作工具的质感。

### 7.4 森林 Moss

- 深墨绿背景；
- 薄荷绿和青灰光晕；
- 柔和的玻璃面板；
- 安静、耐看，适合长时间使用。

### 主题交互

- 设置页使用主题预览卡，而不是单纯色块按钮；
- 主题选择立即预览；
- 主题选择保存在本地；
- 透明效果关闭时，所有主题都提供不透明回退；
- 减少动画时停止动态光晕和大部分转场。

## 8. 插件卡片规范

插件卡片由 Host 统一渲染，内容根据插件提供的数据填充。

### 8.1 紧凑

显示：

- 图标；
- 插件名称；
- 当前状态；
- 一个主要操作；
- 打开详情。

隐藏的指标、列表和说明仍然必须在详情弹窗中存在。

### 8.2 标准

在紧凑模式上增加：

- 一到两个关键指标；
- 第二个必要操作；
- 最近一次操作。

### 8.3 重点

在标准模式上增加：

- 设备或任务列表；
- 进度；
- 多个必要操作；
- 最近活动摘要。

### 尺寸优先级

```text
单个插件的用户尺寸覆盖
  > 全局默认卡片尺寸
```

- 设置中的默认尺寸作用于所有未单独覆盖的插件；
- 单个插件通过更多菜单设置尺寸后，保持自己的尺寸；
- 新安装插件使用当前全局默认尺寸；
- 恢复默认后回到标准尺寸；
- 尺寸变化必须同步改变内容布局，不能只缩放字体。

## 9. 插件详情弹窗

点击卡片或“打开详情”后，打开居中的大弹窗。

### 尺寸

- 默认：720 × 620；
- 最小：560 × 420；
- 最大：920 × 720；
- 随窗口大小适配；
- 不允许用户自由拖拽改变尺寸；
- 只有正文区域滚动；
- 顶部和底部操作栏固定。

### 结构

```text
插件图标 / 名称 / 发布者 / 版本 / 状态 / 关闭

概览 | 操作 | 日志 | 关于

正文区块

固定底部操作栏：状态、主要操作、卸载
```

### 弹窗行为

- 打开时使用淡入和轻微上移；
- 关闭时使用淡出和轻微下移；
- 背景使用 Smoke 遮罩；
- 支持 Esc 和关闭按钮；
- 忙碌状态下禁止误关闭；
- 标签切换只替换正文，不重建整个弹窗；
- 切换标签保留正文滚动位置策略；
- 错误信息和完成结果在弹窗或 Toast 中反馈。

插件可以提供多个通用区块和标签，但不提供自定义 WPF 页面。

## 10. 动画规范

动效用于表达状态变化和空间关系，不用于装饰。

| 场景 | 动画 |
| --- | --- |
| 页面切换 | 220–300ms 淡入和轻微位移 |
| 插件筛选 | 内容先淡出，新卡片按顺序进入 |
| 卡片出现 | 35–45ms 错位延迟 |
| 标签切换 | 只对正文做淡入和轻微位移 |
| 下拉菜单 | 约 170ms 淡入和上移 |
| 按钮悬停 | 轻微颜色、边框和位移变化 |
| 背景光晕 | 缓慢移动，不抢夺注意力 |

必须支持：

- `prefers-reduced-motion`；
- 设置中的“减少动画”；
- 透明效果关闭后的不透明回退。

## 11. 通用插件 UI 边界

Host 支持的通用内容包括：

- 状态区块；
- 指标区块；
- 列表区块；
- 文本输入和搜索；
- 下拉选择；
- 开关；
- 进度条；
- 操作按钮；
- 错误提示；
- 日志列表；
- 空状态和加载状态。

Host 不为具体插件增加：

- 专用 ViewModel；
- 专用 WPF 页面；
- 专用导航项；
- 专用 Plugin ID 判断；
- 专用主题分支；
- 专用卡片布局。

AudioRelay、KeyboardMouse 和未来朋友开发的插件都必须验证同一套通用 Host UI。

## 12. 设置项最终清单

### 外观

- 工作区标题；
- 四套完整主题；
- 动态光晕；
- 减少动画；
- 透明效果；
- 圆角强度；
- 背景亮度；
- 简体中文 / English。

### 插件管理

- 安装插件；
- 默认卡片尺寸：紧凑 / 标准 / 重点；
- 启用前确认；
- 卸载前确认；
- 显示诊断信息。

### 数据与运行

- Config 目录；
- State 目录；
- 日志目录；
- Worker 状态；
- 打开数据目录；
- 恢复默认设置。

### 关于

- ToolBox 版本；
- Plugin API 版本；
- UI 协议版本；
- 软件仓库；
- 插件仓库；
- 当前运行模式和 Host 边界。

## 13. WPF 实现约束

进入 WPF 实现阶段时，优先建立统一的设计令牌：

- `Theme`：背景、玻璃层、文字、边框、光晕、按钮和阴影；
- `Typography`：标题、正文、状态和代码字号；
- `Spacing`：页面、区块、卡片和按钮间距；
- `Radius`：面板、卡片、按钮和菜单圆角；
- `Motion`：页面、卡片、弹窗和标签动画；
- `StateColors`：运行、停用、警告、错误和重启要求。

插件只能提交通用协议数据，不能直接操作这些 Host 设计令牌。

WPF 的实现结果必须与 HTML 预览保持以下一致：

- 信息层级；
- 文字数量和字号；
- 卡片三种尺寸的内容适配；
- 主题整体变化；
- 弹窗尺寸和固定区域；
- 页面和标签动画；
- 插件与 Host 的边界。

## 14. 最终验收清单

- 首屏没有无意义装饰性小字；
- 总览标题可以自定义、实时显示并保存；
- 右上角是设置齿轮，不是主题或强调色入口；
- 四套主题改变完整视觉系统；
- 默认卡片尺寸真实改变未覆盖插件的布局；
- 单个插件尺寸覆盖仍然有效；
- 插件页面筛选有过渡动画；
- 设置子页面有过渡动画；
- 下拉菜单为圆角玻璃样式；
- 详情标签切换不重建整个弹窗；
- 忙碌状态不能误关闭弹窗；
- 1440×900、1920×1080 和窄窗口不重叠；
- 减少动画和关闭透明效果均可用；
- 新增普通插件不需要修改 Host 源码；
- HTML 预览、Host 和插件开发文档对同一 UI 边界描述一致。
